# 隔离修改任务

在工作区页面选择“读写修改（隔离副本）”并填写目标。服务基于管理员批准的只读快照为每个修改任务创建独立副本；任务权限不能由模型改变。在线模型可调用受限 MCP 写工具，可信启动器仅向副本上的现有允许文件发放单次短期写租约。只读任务依然不暴露写工具，也不能获得写租约。

任务完成后，页面列出发生变化的文件。管理员逐个查看原快照和副本内容，勾选确认后才能将选中的文件应用到原项目。Rust 在应用时重新检查修改副本哈希和原文件是否仍与导入时一致，并以单文件替换的方式写入，记录 intent/result 审计；冲突会拒绝。不同文件逐个应用，不是跨文件事务；发生超时或审计故障后，必须检查原文件和审计，不能盲目重试。外部同机进程并发修改文件带来的竞争仍不在强隔离保证范围内。

任务及副本当前保存在服务进程内；重启后失效。仅支持替换已批准的现有 UTF-8 文件，不支持新建、删除、改名或 Shell。无在线模型的离线服务不执行修改任务。不要把密钥写入任务目标或工作区文件，模型可接收其读取的内容。

导入规则新增 `.py`，同时排除 `venv`、`.venv`（隐藏目录规则）和 `__pycache__`；其他允许扩展名及文件大小、数量限制仍有效。原项目改变后，需重新导入才能以新版本为基础创建任务。
