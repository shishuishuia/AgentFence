| 已发现差异 | 当前前端/旧设计 | 已实现后端 | 处理方式 |

| 健康成功响应 | 依赖 `audit_available`、`message` 等 | 只有 `status`、`instance_id` | B 本轮已修正并验证；待与 A 后续提交核对 |

## 3. 按依赖顺序实施

### 阶段一：客户端与独立最小演示

- 在 `integrations/` 建立 Python HTTP 客户端，优先使用标准库，记录实际验证的 Python 版本；管理员客户端负责创建任务、切阶段、发放/撤销租约，Agent 客户端只提交 `read_file/write_file`。
- 工具适配器不能自行读写目标文件。用于验收的检查程序可以读取独立夹具，对比文件内容或哈希，权限要分清。
- `demo/setup.sh` 检查环境并准备独立夹具；`demo/run_minimal.sh` 启动 release 服务、等待健康、执行固定链路并保留结果。支持的正式验收环境沿用 Ubuntu/WSL2，PowerShell 入口可在必要时补充。
- 每次运行生成临时凭证和独立目录，只清理自身进程与临时凭证；写入超时不自动重试。

验收链路：inspect 读成功/写拒绝 → edit 发放一次性租约 → 写成功 → 再写返回 `LEASE_USED_UP` → 区外路径拒绝 → verify 读回/写拒绝 → done 读拒绝 → 核对审计关联。全部通过才输出 `MINIMAL_DEMO_PASS` 并退出 0。

产物：`minimal_demo.json`、`demo_events.jsonl`、运行清单及脱敏断言结果。此入口独立于浏览器和在线模型。

### 阶段二：只读代理与正式页面托管

`web_proxy/` 建议沿用 Python，保持依赖简单。固定监听 `127.0.0.1:4173`，只映射：

| 浏览器接口 | Rust 上游 |
| --- | --- |
| `GET /api/health` | `GET /healthz` |
| `GET /api/tasks` | `GET /v1/admin/tasks` |
| `GET /api/tasks/:id` | `GET /v1/admin/tasks/{id}` |
| `GET /api/events` | `GET /v1/admin/events` |

- Admin Token 从代理环境读取；浏览器凭证不转发。固定回环上游，校验 ID、参数、Host 和有值的 Origin。
- 不透传任意 URL，不暴露管理写接口；非 GET、未知 API 和非法查询返回明确 JSON 错误。
- 保留上游状态码及 `reason_code`；连接失败为 502 `BROKER_UNAVAILABLE`，5 秒超时为 504 `BROKER_TIMEOUT`，设置 `no-store`。
- 托管 `front/dist`。页面深链接可回退 `index.html`；API 错误和缺失静态资源不可回退成 HTML。静态路径也必须限制在 dist 内。

验收：四条查询与直接访问 Rust 的数据一致；POST 被拒；伪造上游地址不生效；凭证不出现在浏览器或构建产物；开发模式与 dist 模式都能直接刷新详情页。

### 阶段三：前端真实数据与生命周期

| 页面 | 必做内容 |
| --- | --- |
| 总览 | 服务状态、实例、最近任务、当前加载范围的事件统计 |
| 任务列表 | 阶段、时间、详情入口、`total/truncated` 与“最近任务”提示 |
| 任务详情 | 阶段、允许路径、服务端租约状态、剩余次数、关联事件 |
| 审计 | 任务及结果筛选、游标增量加载、请求关联、未确认 intent |

共用轮询放在 `src/composables/`：进入立即加载，默认每秒查询，上一轮未结束不启动下一轮；离开取消请求。任务切换清空游标，旧响应不能覆盖新页面。使用实例 ID 与事件 ID 去重，实例变化提示重启并清空旧任务数据。断线保留已加载数据并标明更新时间。

只对 `event_type=result` 统计；管理事件排除，intent 不算完成。按后端契约区分成功、策略拒绝和输入/身份/I/O 等失败。筛选条件写入路由 query，`result` 只筛选已加载事件。租约倒计时只用于展示，不推断最终授权。

验收 F01～F04：路由/刷新/前进后退、空与失败状态、取消与无重复轮询、构建及网络无凭证。Vitest 重点覆盖请求竞争、停止轮询、重启和结果分类；保留实际浏览器验收记录。
