# AgentFence Lite 项目功能与使用说明

本文介绍当前版本的功能和操作方法，面向首次使用项目的同学。需要查看接口和实现细节时，可继续阅读文末的相关文档。

## 1. 项目是什么

AgentFence Lite 是一个基于 Rust 的 Agent 工具调用权限控制与审计原型。用户先导入项目快照，再创建任务；任务通过受控工具访问文件，Rust Broker 根据任务身份、阶段、路径权限和写入租约决定是否执行，并记录审计事件。

当前界面支持两类任务：

- **只读审查**：读取导入时生成的项目快照，给出审查结果，不修改原项目。
- **读写修改（隔离副本）**：先在独立副本中修改已授权文件；任务完成后，管理员可以逐文件查看修改并确认应用到原项目。

工具调用网关的控制范围仅覆盖**经过网关的操作**。项目本身不是操作系统沙箱，不能保证拦截其他程序绕开网关直接访问宿主机。

## 2. 当前能力与状态

| 功能 | 当前状态 |
| --- | --- |
| 导入工作区 | 通过系统文件夹选择器选择项目，预览允许和排除的文件，确认后生成快照。 |
| 只读审查 | 可使用真实 DeepSeek 模型；也可选择离线模式验证 MCP 与审计，但离线模式不生成模型建议。 |
| 隔离修改 | 使用在线模型修改副本中的已授权现有文件，管理员确认后逐文件应用。 |
| 任务与审计 | 查看任务阶段、工具调用结果、请求标识和审计事件。 |
| 前端 Agent 选择 | 在工作区的任务创建区域选择已配置的运行方式并启动任务。 |
| 外部 DeepSeek Harness | 已完成独立实验和通信组件原型；正式运行器尚未接通，页面显示不可用。 |

页面中的 **DeepSeek（内置）** 表示项目自己的任务编排程序调用 DeepSeek API，不代表外部 DeepSeek Harness、Claude Code 或 Codex 已接入。

## 3. 主要组成

| 目录或文件 | 作用 |
| --- | --- |
| `crates/core/` | 任务阶段、策略、路径、租约与错误原因等核心规则。 |
| `crates/server/` | Rust Broker、HTTP 接口、工作区快照、文件操作和审计。 |
| `crates/mcp-server/` | MCP stdio 服务，将任务工具调用转发到 Rust Broker。 |
| `web_proxy/` | 本地管理助手、系统目录选择器、浏览器接口和前端文件托管。 |
| `integrations/` | MCP 客户端、DeepSeek 模型调用和外部 Harness 的实验性通信组件。 |
| `front/` | Vue 前端，包括工作区、任务列表、任务详情和审计页面。 |
| `demo/run_v2_dashboard.py` | 启动独立的本地 Broker、管理助手和前端服务。 |

文件和模型回复都不决定是否授予权限；权限判断由 Rust Broker 执行。管理员凭证和任务凭证保留在服务端，不由浏览器输入。

## 4. 环境准备与启动

以下示例面向 Windows PowerShell。需要安装 Rust 工具链（仓库的 `rust-toolchain.toml` 固定版本并包含 `rustfmt`、`clippy`）、Python 3.12（含 `tkinter`）、Node.js 及 npm。首次构建和安装依赖需要网络。

在仓库根目录执行：

```powershell
cd C:\Users\33740\Desktop\AgentFence

# 准备独立 Python 环境和 MCP 客户端依赖
python -m venv target/user-guide-venv
.\target\user-guide-venv\Scripts\python.exe -m pip install -r integrations/requirements-mcp.txt

# 构建 Rust 服务和 MCP 程序；使用独立目录，避免覆盖正在运行的程序
cargo build --workspace --release --locked --target-dir target/user-guide-v2

# 安装前端依赖并构建页面
npm --prefix front ci
npm --prefix front run build
```

其他电脑请将 `cd` 后的路径替换为自己的仓库位置。如果系统没有可用的 Rust 编译器或链接器，应先配置对应工具链。

### 4.1 离线模式

```powershell
.\target\user-guide-venv\Scripts\python.exe -m demo.run_v2_dashboard --bin-dir target/user-guide-v2/release --port 4180 --agent offline
```

终端出现 `v2_dashboard_ready` 后，打开 <http://127.0.0.1:4180/workspaces>。离线模式会使用真实 Rust MCP 和审计进行固定的只读调用，**不会调用模型或生成模型审查建议，也不支持修改任务**。

### 4.2 DeepSeek 在线模式

先在启动服务的 PowerShell 窗口中安全输入自己的 API Key，不要把密钥写入命令、任务目标、项目文件或提交记录：

```powershell
$secret = Read-Host '请输入 DeepSeek API Key' -AsSecureString
$env:DEEPSEEK_API_KEY = [Net.NetworkCredential]::new('', $secret).Password
$env:DEEPSEEK_MODEL = 'deepseek-flash'

.\target\user-guide-venv\Scripts\python.exe -m demo.run_v2_dashboard --bin-dir target/user-guide-v2/release --port 4180 --agent deepseek
```

打开 <http://127.0.0.1:4180/workspaces>。在线任务需要可用的 API Key、网络及账户额度。任务文字和模型读取到的文件内容会发送给 DeepSeek；请先确认项目内容适合发送。

同一端口一次只能运行一个服务。结束时在启动窗口按 `Ctrl+C`；服务退出后，可用 `Remove-Item Env:DEEPSEEK_API_KEY` 清除该窗口的环境变量。示例中的 4180 只是建议端口，已被占用时可调整 `--port`。

## 5. 导入项目快照

1. 打开「工作区管理」，点击 **选择本机文件夹**，在系统窗口中选择项目目录。
2. 检查预览中的允许文件和排除项。至少准备 3 个允许导入的文件，以满足当前内置只读审查的初始读取要求。
3. 根据页面提示检查排除项，填写工作区名称，点击 **确认导入项目快照**。
4. 在「已导入工作区」中找到该工作区，然后创建任务。

默认允许导入的文件扩展名为 `rs`、`py`、`toml`、`md`、`txt`、`json`、`yaml`、`yml`。隐藏项、依赖或构建目录、常见凭证文件名及链接等会被排除；具体清单以页面预览为准。文件名过滤不能识别所有敏感内容，请人工检查。

快照保存导入时批准的文件内容；原项目后来改变不会自动更新快照。需要使用新的内容时，请重新预览并导入。

## 6. 创建并查看只读任务

1. 在目标工作区选择 **只读审查**。
2. 在「选择 Agent」中选择可用的 **DeepSeek（内置）**；离线服务则显示 **离线演示（内置）**。
3. 填写任务目标，例如：“检查项目主要文件，说明功能并提出有文件路径依据的改进建议。”
4. 点击 **创建并启动任务**，进入任务详情页。
5. 观察状态、工具调用次数、已读取文件数、报告和关联审计。模型建议仍需人工复核。

任务详情里的 `inspect → verify → done` 表示受控流程的阶段。完成表示该次流程及其要求的核验已结束，并不证明模型建议或项目功能一定正确。

## 7. 创建隔离修改任务并确认应用

1. 使用在线模式启动服务，在工作区选择 **读写修改（隔离副本）**。
2. 选择可用的内置运行器，填写具体目标，例如：“检查已有文件中的输入校验，并在隔离副本中修复明确的问题。”
3. 点击 **创建并启动任务**。系统先在独立副本上执行受控操作；写入需要对应文件的短期、限次租约。
4. 任务完成后，在修改清单中点击 **查看修改**，比较原始内容与修改后内容。
5. 如果确认该文件可以应用，勾选确认框并点击 **确认应用到原项目**；其他文件需要分别确认。

当前仅支持替换已批准的现有 UTF-8 文件，不支持通过该流程新建、删除或重命名文件，也不提供 Shell。应用前会检查原文件和副本内容是否仍符合预期；如果发生冲突、错误或超时，先检查原文件与审计记录，不要盲目重试。多个文件逐个应用，不是跨文件事务。

## 8. 查看连接、任务和审计

- 左侧主菜单下方显示 **服务连接**、当前实例、上次成功时间和 **重新加载** 按钮；断开时可通过提示检查服务。
- 「任务列表」展示当前实例中的任务；点击任务可查看详情、阶段、允许路径、租约和报告。
- 「审计事件」展示操作意图和结果，可按任务等条件筛选。文件工具调用的 `request_id` 可用于对应页面记录与 Broker 审计。

当前任务、快照和管理状态依赖运行中的服务实例；**服务重启后旧任务不会自动恢复**，需要重新导入项目并创建任务。

## 9. 常见问题

**外部 DeepSeek Harness 为什么不可选？**

正式运行器还未接入当前服务，即使电脑上已经安装 Harness 也不会自动启用。已有实验验证不等于页面功能完成；进度和安全边界见 [外部 Harness 接入进度](external-harness-integration.md)。

**为什么不能创建修改任务？**

离线演示仅用于只读重放。请使用 `--agent deepseek` 启动在线服务，并确认密钥、网络和账户状态正常。

**任务启动后显示失败怎么办？**

先查看任务详情和审计中的错误或拒绝原因；检查服务连接、项目快照和模型配置。创建或启动结果不确定时，先查看任务列表或已有任务详情，避免重复创建或重复执行。

**服务重启后为什么找不到原任务？**

当前实现不承诺跨服务重启恢复任务或快照，重新导入项目并创建任务即可。
